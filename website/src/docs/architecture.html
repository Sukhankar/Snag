DEVELOPER FIELD GUIDE / 03

One stack, clear boundaries.

The API owns persistence and authorisation. The widget and dashboard provide two different views of the same conversation.

Request path

Client app / Preact widget ── reports ──┐
                                       ▼
                                  Go API ── PostgreSQL
                                       ▲
Next.js dashboard ── server proxy ──────┘

Live updates return over Server-Sent Events.
ModuleOwns
server/Go API, auth, permissions, SQL migrations, attachment validation, SSE broker, widget hosting.
widget/Preact interface, telemetry, compression, reporter identity.
dashboard/Next.js interface, HttpOnly session cookie, allow-listed API proxy.
e2e/Browser checks for reporting, dashboard workflows, users and roles.

A ticket is one transaction

The API validates the report and attachments, then stores the ticket, initial message, and attachment rows in a transaction. Public and internal messages use separate visibility rules. Widget queries are scoped to the project and reporter token.

Live updates

The in-process broker fans out ticket and message events. Slow clients are disconnected and may reconnect. Run a single API replica until a shared event transport is implemented.

Storage

PostgreSQL stores metadata and base64 attachment payloads. Migrations are embedded in the API binary and run at startup. Compose uses a named pgdata volume.

Where to read next

See the repository’s implementation notes for keyset pagination, duplicate handling, and storage tradeoffs.
