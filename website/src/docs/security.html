DEVELOPER FIELD GUIDE / 06

Access follows the user.

Permissions are enforced on the API, including when the dashboard hides an unavailable action.

Owner and roles

The Owner cannot be deactivated or assigned another role and has all permissions. Default roles are Admin, Developer, Support Agent, and Viewer. Use the Roles grid to change permissions or create a role.

A user cannot grant a permission they do not hold, or edit a user with more permissions. Role changes apply on the next request. Password resets and deactivation revoke sessions.

Sessions

Passwords use Argon2id. The API stores only a SHA-256 hash of a session token. The dashboard stores the opaque token in an HttpOnly, SameSite=Lax cookie and forwards it as a bearer token through its server-side proxy.

Reporter isolation

Widget queries use both project identity and the reporter token. Internal notes are excluded from reporter queries and live events. Project keys identify integrations; the origin allowlist is a browser control, not proof of identity for arbitrary HTTP clients.

Operational boundaries

  • Use HTTPS in deployed environments and keep secure cookies enabled.
  • Keep admin service tokens server-side; leave the optional token unset when unused.
  • Review screenshots, attachments, and error messages for sensitive data.
  • SSO, OIDC, and two-factor authentication are not implemented.

Report a security issue

Contact the repository owner privately through your existing project contact channel. Do not paste credentials or exploit data into a public issue.
