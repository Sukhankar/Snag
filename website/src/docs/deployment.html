DEVELOPER FIELD GUIDE / 08

Operate the whole conversation.

The supplied Compose stack targets a single host with one realtime API replica.

Before exposing the service

  1. Set unique database and Owner passwords. Omit the optional admin token unless needed.
  2. Place the dashboard and public widget/API endpoint behind an HTTPS reverse proxy.
  3. Set project origin allowlists to the actual client applications.
  4. Keep COOKIE_SECURE enabled. Forward SSE without response buffering.
  5. Restrict direct access to application ports as appropriate for your reverse proxy.

Compose publishes API port 8080 and dashboard port 3000. PostgreSQL is on the internal Compose network. Enable SNAG_TRUST_PROXY only when the proxy overwrites forwarded client-IP headers.

Build and inspect

Terminal
docker compose up --build -d
docker compose ps
docker compose logs -f server

Persistence and backups

The pgdata volume contains the database, including attachment payloads. Store backups outside the repository and protect them as application data.

Terminal
docker compose exec -T postgres pg_dump -U snag -d snag -Fc > snag-backup.dump

Validate restores against a separate PostgreSQL instance before relying on a backup. docker compose down retains data; docker compose down -v deletes the volume.

Owner recovery

Terminal
read -rs -p 'New password: ' SNAG_NEW_PASSWORD; echo
export SNAG_NEW_PASSWORD
docker compose run --rm -e SNAG_NEW_PASSWORD server set-password owner@example.com
unset SNAG_NEW_PASSWORD

Replace the email with the account to reset.

Upgrades and scaling

Back up before an upgrade, review embedded SQL migrations, rebuild, and check health plus a report/reply flow. Migrations run at API startup. Multiple API replicas need a shared event transport; the current broker is process-local.
